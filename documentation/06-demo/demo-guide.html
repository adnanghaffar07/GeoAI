1The app in one minute

GeoInfraLens AI helps a city road department find road and sidewalk problems (potholes, cracks, damaged pavement) from survey photos, see them on a map, and decide what to inspect first.

  1. A field collector takes photos with a phone on the street. The phone stores the GPS location and time inside each photo.
  2. The photos are uploaded into a project. The app reads the location and time and checks the quality (blurry, too dark, outside the survey area).
  3. AI looks at each photo and suggests possible problems. (next phase, P5)
  4. A technical reviewer (a person) confirms or rejects every AI suggestion. The AI never decides on its own. (P6)
  5. Confirmed problems appear on the map, get an inspection priority, and go into reports. (P7)
One line to say"The AI only suggests. A qualified person checks every suggestion before it counts, and every change is recorded."

  • Secure sign-in, sign-out, and automatic lock after 5 wrong passwords in 15 minutes.
  • Inviting people by one-time link, accepting the invitation, and setting a password.
  • Password reset links created by an administrator.
  • Organization roles (Administrator, Manager, Member) and project roles (Project manager, Field collector, Technical reviewer, Viewer).

3Start the demo

Two windows: one for the backend (server and database), one for the frontend (the screens). Open Docker Desktop first and wait for "Engine running".

Window 1: backend

cd "C:\Users\Developer2025\Desktop\GeoInfraLens AI"
docker compose up --build

Window 2: frontend

cd "C:\Users\Developer2025\Desktop\GeoInfraLens AI\frontend"
npm run dev

Then open http://localhost:5173 for the app and http://localhost:8000/api/docs for the API list.

Before the meetingRun through the demo script once. Have 3–5 phone photos ready (with location on), one screenshot (no location), one .txt file, and one GeoJSON file from geojson.io. Use a second email address for the invitation step.

4Demo script (about 15 minutes)

  1. Sign in. Show the eye button on the password box. Mention passwords are stored scrambled (hashed), never as plain text.
  2. Overview. Show System status: database ok, queue ok.
  3. Team. Read the blue-yellow note about organization roles and project roles. Invite a person and show the one-time link with Copy.
  4. Accept the invitation in a private browser window: enter a name and password, and sign in as that person.
  5. Create a project. Press Save with everything empty to show the messages beside each field. Then fill it in and draw the survey area on the map. Create a second one from a GeoJSON file.
  6. Team tab of the project. Add the invited person as Field collector.
  7. Upload photos. Tick the permission box. Add phone photos, a screenshot and a .txt file. Show the progress bars, "No location" for the screenshot, and the clear refusal for the .txt file. Upload one photo again to show "Already uploaded".
  8. Photos tab. Show warnings (blurry, no time zone), the location source, and use Pick location on map for the screenshot.
  9. Overview tab. Show the counts and the dots on the map.
  10. Permissions. Sign in as the field collector: they see only their project and only their own photos.
  11. Phone view. Press F12, then Ctrl + Shift + M, and pick a phone size.
  12. Behind the scenes. Open /api/docs, and show the console messages in the backend window and the browser (F12 → Console).

7One-time links (invitations and password resets)

No email service is connected yet, so the administrator copies the link and sends it themselves (email, chat).

  1. The server creates a long random code using Python's secrets module (the standard tool for security codes). It cannot be guessed.
  2. The database stores only a scrambled fingerprint of the code (SHA-256), never the code itself. Even someone who reads the database cannot use the links.
  3. The full link is shown once on screen with a Copy button. It is never shown again.
  4. When someone opens the link, the server scrambles the code the same way and looks for a match.
  5. The link works once. Invitations expire after 7 days, reset links after 1 hour. A newer link replaces older ones. Using a reset link signs the person out everywhere.
  6. The code is hidden as *** in all console messages.
One line to say"Links are random, single-use, time-limited, and the database never stores them readable."

PartTechnologyPlain explanation

Street backgroundOpenFreeMap tilesFree street map pictures. Can be swapped with one setting (VITE_MAP_STYLE_URL). Terms to be checked before the pilot.

Map filesGeoJSONThe standard text format for map shapes; GIS tools such as QGIS export it.

If the street background cannot load (offline), the map shows a plain background and drawing still works. Photo locations are treated as approximate camera positions, and a photo without GPS is never given an invented location.

9The API and the Swagger page

The API is the list of requests the screens can send to the server. FastAPI publishes it automatically as an interactive page (Swagger UI).

  • Open: http://localhost:8000/api/docs while the backend runs. Every request is listed with its inputs, outputs and possible errors, and can be tried there.
  • Machine-readable version: http://localhost:8000/api/openapi.json (the OpenAPI standard).
  • The Swagger page is switched off in production for security.
  • All addresses start with /api/v1. "v1" means version 1: later changes only add new requests, so nothing that works today breaks.
  • Every error has the same shape: a code, a plain message, details, and a request ID for support.

10How the frontend talks to the backend

sequenceDiagram
    participant B as Browser (React screens)
    participant V as Vite dev server :5173
    participant A as FastAPI backend :8000
    participant D as PostgreSQL + PostGIS
    B->>V: POST /api/v1/auth/login
    V->>A: forwards /api/... (proxy)
    A->>D: check password hash
    D-->>A: user found
    A-->>B: 200 + session cookie (httpOnly)
    B->>V: GET /api/v1/organizations/{id}/projects (cookie sent)
    V->>A: forwards
    A->>A: who is this? allowed?
    A->>D: projects this person may see
    A-->>B: JSON list → screen shows cards
  1. One address. The browser only talks to localhost:5173. Vite forwards anything starting with /api to the backend on port 8000. In production the same happens on one web address.
  2. One helper. All screens call the backend through one file (src/lib/api-client.ts). It sends JSON, reads answers, and turns every failure into the same error shape.
  3. Session cookie. After sign-in the server sets a cookie the page's code cannot read (httpOnly). The browser sends it automatically; the server looks up who it is on every request. Signing out or being removed ends it immediately.
  4. Permission on every request. The server checks the person's organization and project roles for each request. Another organization's data returns "not found".
  5. Caching and refresh. TanStack Query keeps fetched data, shows loading skeletons, and refreshes lists after a change (for example after an upload).
  6. Photo upload uses a direct browser upload (XMLHttpRequest) so each file can show its own progress bar.
  7. Request ID. Every request gets an ID. Errors show it as "Reference" so a problem can be found in the server console.

12Likely questions from the lead

Does the AI work yet?
Not yet. P5 adds the AI step with a test detector so the whole flow can be built and tested. The real model is trained in P8, once the customer gives photos and permission.
Can one customer see another customer's data?
No. Every request is checked against the person's organization and project roles, and there are automatic tests that try to read other organizations' data and must fail.
Where are photos stored? Is it secure?
In a private storage area on the server, never on a public address. A photo is sent only after a permission check, every time. The original is never changed; a small preview is made for screens.
What if a photo has no GPS?
It is flagged "No location" and nothing is guessed. Someone picks the spot on the map, and it is labelled "Picked on map".
What happens if an upload fails or is sent twice?
Each file can be retried. The server recognises a file it already has by its fingerprint and never stores it twice.
Can we change colours, login method, or hosting later?
Yes. Colours live in one file. Sign-in code is in one place, so Google or Microsoft single sign-on can be added later. The app runs in Docker, so it can move to any server or cloud.
Is it tested?
Yes: 113 automatic backend tests and 30 frontend tests, plus browser walk-throughs at computer and phone size for each phase.
What does it cost to run?
The software is all free and open source. Costs will be the server and storage for the pilot, decided in P10.
What is needed from the customer?
Permission to use their photos for AI training, a qualified engineer to review findings, agreed accuracy targets, and their list of defect types and severity rules.
Full project documentation is in the documentation folder of the project, starting with CURRENT_PHASE.md.
